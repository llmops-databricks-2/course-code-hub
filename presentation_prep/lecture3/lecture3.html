Instructions

ANTHROPIC’S DISTINCTION (PARAPHRASED)

LLM workflows versus agents

The distinction is who directs the process and tool use.

LLM workflows

  • Code defines the paths through the model and tools.
  • Developers control the order and branching.
  • Useful for repeatable, well-defined tasks.

The LLM follows a predefined process.

Agents

  • The model decides which step to take next.
  • It selects tools and adapts to their results.
  • Useful when the task needs flexible decisions.

The LLM directs the process as it runs.

Workflows: control in code. Agents: control in the model.

Source: Anthropic: Building effective agents

OUR COURSE DEFINITION

Agent = LLM with tool control

Following the OpenAI Agents SDK model of an agent.

An agent has:

  • An LLM with instructions
  • Access to tools, such as APIs or functions
  • The ability to decide when and how to use them
The decision to use the tool is the key.

The LLM chooses the tool call: agent.

Application code predetermines the tool call: workflow.

The application executes tool requests in both cases. This is our course distinction, not a universal definition.

RAG

Simple RAG versus agentic RAG

Simple RAG

User question → application retrieves chunks → application builds a prompt → model answers.

Retrieval is fixed and happens outside the model.

RAG as a tool

User question → model decides to call search_papers() → tool returns chunks → model answers.

The model controls when and how retrieval happens.

Lecture 2 built the retrieval layer. Lecture 3 gives the model control over it.

Our pgvector search remains the same. The change is the interface: instead of always retrieving first, we expose search as a tool that an agent can call when appropriate.

MCP

MCP versus custom functions

QuestionMCP serverCustom function
SetupConnect to an existing server.Write and register Python code.
ReuseOne server can support many agents.Usually designed for one application.
SecurityAuthentication and authorization can be managed centrally.The application owns the security implementation.
CustomizationUse the capabilities the server exposes.Implement custom business logic directly.
Use MCP for standard operations. Use custom functions when the application needs specialized logic.

MCP is valuable when a capability should be reused across applications. Custom functions remain the better choice when we need full control over logic and data access.

MCP

Why use MCP?

Standardized

Agents use a common protocol across different systems.

Reusable

One server can expose a capability to many agents.

Managed

The platform can operate the server and its connections.

Enterprise ready

Authentication, authorization, and scaling are part of the platform design.

MCP does not remove the need for good tool design. It gives us a consistent connection layer so agents can discover and invoke tools safely.

UNITY CATALOG

UC functions as governed MCP tools

Define once

CREATE FUNCTION llmops_dev.arxiv.add_numbers(a DOUBLE, b DOUBLE) RETURNS DOUBLE LANGUAGE PYTHON RETURN a + b;

Expose through MCP

server = "/api/2.0/mcp/functions/llmops_dev/arxiv"; client discovers the function; model can call it
Why MCP? UC governance, permissions, lineage, and reuse stay in place while agents get a standard discovery and tool-calling interface.

Use direct SQL when the workflow is fixed. Use UC Functions MCP when multiple agents need governed, discoverable functions.

A Unity Catalog function is governed reusable logic. Databricks can expose it through MCP so an agent can discover and invoke approved functions without embedding database-specific details in every application. MCP is most useful when the same functions should be shared across agents and clients.

COURSE IMPLEMENTATION

Connect the Genie Agent through MCP

from databricks.sdk import WorkspaceClient
from arxiv_curator.mcp import create_mcp_tools
import asyncio

w = WorkspaceClient()
genie_url = (
    f"{w.config.host}/api/2.0/mcp/genie/"
    f"{cfg.genie_space_id}"
)
genie_tools = asyncio.run(create_mcp_tools(w, [genie_url]))

# One agent, two capabilities
tools = [search_papers_tool, *genie_tools]

create_mcp_tools is our course helper: it discovers tool schemas and creates callables for the agent loop.

Notebook 3.2 provides cfg and search_papers_tool. The Genie Agent and its underlying data must be accessible to the calling identity.
